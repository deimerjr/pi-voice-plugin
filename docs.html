ARQUITECTURA DEL SISTEMA Y CICLO DE VIDA

[ESTABLE]

Pi Voice Plugin es una extensión modular de alto rendimiento para el entorno Pi CLI. Se integra en el bucle de eventos del agente mediante interceptores de ciclo de vida, sanitiza y resume las respuestas en tiempo de ejecución, aplica exclusión mutua inter-proceso mediante cerrojos POSIX y sintetiza voz en tiempo real con baja latencia.

[01.1] VISIÓN GENERAL & DIAGRAMA DE FLUJO

El flujo de procesamiento de voz desacopla la generación de texto del motor de síntesis de audio, garantizando que el modelo no se bloquee durante la lectura ni se generen ruidos por fragmentos de código o trazas de razonamiento interno.

+-----------------------------------------------------------------------------+ | PI CLI RUNTIME | | +-------------------+ +---------------------+ +----------------+ | | | User Prompt / CLI | ---> | LLM Agent Execution | ---> | Tool Execution | | | +-------------------+ +---------------------+ +----------------+ | +----------------------------------------|------------------------------------+ | [Event Bus: agent_end, tool_*] v +-----------------------------------------------------------------------------+ | PI-VOICE-PLUGIN ENGINE | | | | +---------------------+ +--------------------+ | | | DecisionsGate | -----> | TextSanitizer | | | | - decisionsOnly | | - Omit/Mention code| | | | - Tool Detection | | - Strip | | | +---------------------+ +--------------------+ | | | | | | v v | | +---------------------+ +--------------------+ | | | TldrSummarizer | -----> | ConcurrencyLock | | | | - Low/Med/High | | - POSIX /tmp FIFO | | | | - Spanish Barrier | | - Queue/Focus/PID | | | +---------------------+ +--------------------+ | | | | | v | | +-----------------------------------------------------------------------+ | | | AudioPlayer -> Auto-Detect Player (pw-play, paplay, aplay, afplay) | | | +-----------------------------------------------------------------------+ | | | | | v | | +-----------------------------------------------------------------------+ | | | TTS Provider Layer: | | | | [1] KokoroProvider (Local ONNX, 0 Tokens, 120ms TTFA) | | | | [2] OpenAIProvider (Cloud API, tts-1) | | | | [3] ElevenLabsProvider (Cloud API, Multilingual v2) | | | | [4] CustomHttpProvider (Generic Endpoint) | | | +-----------------------------------------------------------------------+ | +-----------------------------------------------------------------------------+

[01.2] HOOKS DE CICLO DE VIDA Y EVENTOS DEL AGENTE

El plugin escucha tres eventos fundamentales emitidos por el núcleo de Pi para orquestar la locución de estado y la entrega final de respuestas:

Hook Pi CLI Payload Interceptado Comportamiento de Voz Condición de Disparo
tool_execution_start { toolName, args } Anuncia el inicio de ejecución de herramienta o subagente ("Explorando con Dora...", "Ejecutando pruebas..."). Siempre que subagents.enabled sea true y decisionsOnly no lo silencie.
tool_execution_end { toolName, result, isError } Sintetiza el resultado o veredicto de la herramienta con traducción automática al español nativo. Filtra herramientas internas y solo vocaliza cambios sustanciales o fallos.
agent_end { message: { content, role } } Procesa el texto de salida mediante DecisionGate, TextSanitizer y TldrSummarizer antes de enviarlo a la cola de audio. Activado si autoRead es true o si DecisionGate detecta una pregunta interactiva.

[01.3] MÓDULOS DEL NÚCLEO (CORE ENGINE)

La arquitectura interna se divide en 8 subsistemas desacoplados con responsabilidades únicas y pruebas unitarias aisladas:

Archivo Componente Responsabilidad Técnica
src/index.ts VoiceExtension Entrypoint Registro del plugin, comandos CLI /voice, atajos globales de teclado e integración con Pi context.
src/decision-gate.ts DecisionGate Heuristics Detección inteligente de preguntas interactivas y herramientas de confirmación para el modo decisionsOnly.
src/tldr.ts TldrSummarizer Engine Resumen predictivo en 3 niveles (low, medium, high) con barrera idiomática estricta hacia el español.
src/lock.ts PlaybackLockManager Control de concurrencia inter-proceso mediante tickets en /tmp/pi-voice-<uid>/ y chequeo de PID.
src/menu.ts VoiceMenuComponent Interfaz modal interactiva TUI para navegación por teclado/ratón sin abandonar la sesión de la terminal.
src/sanitizer.ts TextSanitizer Eliminación de fences markdown, bloques de código (omit/mention), tags <think> y segmentación oracional.
src/player.ts AudioPlayer Manager Reproducción de buffers WAV/MP3, escalado lineal de amplitud PCM y terminación atómica de procesos de sonido.
src/providers/* TTS Providers Factory Adaptadores HTTP para Kokoro ONNX local, OpenAI TTS, ElevenLabs y endpoints REST custom.

[01.4] FACTORY DE PROVEEDORES Y SANITIZACIÓN

Ejemplo de cómo la fábrica instancía el proveedor TTS adecuado y cómo el sanitizador purga bloques sintácticos antes de invocar el motor de voz:

src/providers/factory.ts // Instanciación tipada de proveedores
TYPESCRIPT 
import { TTSProvider, VoiceConfig } from "../types.js";
import { KokoroProvider } from "./kokoro.js";
import { OpenAIProvider } from "./openai.js";
import { ElevenLabsProvider } from "./elevenlabs.js";
import { CustomHttpProvider } from "./custom.js";

export function createTTSProvider(config: VoiceConfig): TTSProvider {
  switch (config.provider) {
    case "kokoro":
      return new KokoroProvider(config.providers?.kokoro);
    case "openai":
      return new OpenAIProvider(config.providers?.openai);
    case "elevenlabs":
      return new ElevenLabsProvider(config.providers?.elevenlabs);
    case "custom":
      return new CustomHttpProvider(config.providers?.custom);
    default:
      throw new Error(`[PiVoice] Proveedor no reconocido: ${config.provider}`);
  }
}
[MOD::02]

CONCURRENCIA INTER-PROCESO Y CERROJOS FIFO

[POSIX_IPC]

Cuando trabajas con múltiples terminales o subagentes de Pi corriendo en paralelo sobre distintos repositorios, los procesos compiten por el mismo dispositivo de salida de audio del sistema operativo. Sin sincronización, las voces se solaparían creando una cacofonía ininteligible.

[02.1] ARQUITECTURA IPC EN /tmp/pi-voice-<uid>/

Pi Voice Plugin resuelve la coordinación entre procesos independientes mediante un directorio IPC aislado por usuario en el sistema de archivos temporal de Linux/macOS:

[!] DIRECTORIO DE AISLAMIENTO POSIX

Ruta canónica: /tmp/pi-voice-<UID>/ (ej: /tmp/pi-voice-1000/). Con permisos 0700, asegurando que ningún otro usuario local pueda espiar o alterar los cerrojos de reproducción.

/tmp/pi-voice-1000/ |-- playback.lock <- Lease atómico con PID del proceso reproductor activo |-- active_session.json <- Identificador de sesión con foco y timestamp de actividad `-- queue/ <- Directorio de tickets FIFO |-- 1726910000000_14205.ticket <- Sesión A (PID 14205, esperando turno) `-- 1726910000150_14890.ticket <- Sesión B (PID 14890, siguiente en cola)

Antes de comenzar a reproducir audio, cada proceso escribe un ticket atómico con timestamp. La cola se ordena de manera lexicográfica garantizando un estricto orden FIFO (First-In, First-Out). Si un proceso termina inesperadamente (SIGKILL / crash), el supervisor verifica la vivacidad del PID mediante kill(pid, 0) y purga los tickets huérfanos sin bloquear el sistema.

[02.2] COMPARATIVA DETALLADA DE LOS 4 MODOS DE COLA

Modo Estrategia de Cerrojo Comportamiento ante Colisión Caso de Uso Recomendado
queue (Default) Cola FIFO Cooperativa Espera a que el audio anterior termine y reproduce inmediatamente en estricto orden cronológico. Flujo estándar de trabajo cuando quieres escuchar todas las respuestas completas.
interrupt Desalojo Preemptivo Envía SIGTERM al reproductor activo, limpia el cerrojo anterior y toma el control de voz de inmediato. Sesiones interactivas donde la respuesta más reciente siempre tiene máxima prioridad.
focus Aislamiento de Sesión Activa Solo reproduce voz si la sesión emisora es la que actualmente tiene foco en la terminal; suprime las demás. Múltiples terminales abiertas en mosaico; silencia procesos en segundo plano.
off Sin Control de Concurrencia Bypasea todos los cerrojos y reproduce de forma concurrente en el bus de audio. Entornos de pruebas o depuración de rendimiento sin exclusión mutua.

[02.3] PREFIJO DE PROYECTO (announceProject)

Al trabajar en múltiples repositorios a la vez, la opción announceProject prefija inteligentemente las respuestas con el nombre del directorio base del proyecto actual:

[03.2] PARÁMETROS GLOBALES Y DE PROVEEDORES

Propiedad Tipo Default Descripción
provider string "kokoro" Motor TTS activo: "kokoro", "openai", "elevenlabs", "custom".
autoRead boolean false Si está activo, lee en voz alta cada mensaje final emitido por el asistente.
decisionsOnly boolean false Filtro inteligente: solo habla cuando el modelo requiere una confirmación o decisión humana.
concurrencyMode string "queue" Estrategia de exclusión mutua de audio: "queue", "interrupt", "focus", "off".
tldrLevel string "medium" Profundidad del resumen antes de hablar: "low" (extenso), "medium" (balanceado), "high" (ultra-conciso).
userTitle string "Líder" Apelativo de respeto con el que los agentes se dirigen al desarrollador (ej: "Jefe", "Comandante").

[MOD::04]

KOKORO TTS LOCAL Y CERO TOKENS DE IA

[OFFLINE_ONNX]

Kokoro es un modelo de síntesis de voz neuronal de vanguardia con 82 millones de parámetros, optimizado para ejecutarse en CPU/GPU local mediante ONNX Runtime. Garantiza privacidad absoluta, funcionamiento sin conexión a internet y cero consumo de tokens o llamadas de API de pago.

[04.1] GARANTÍA DE CERO TOKENS & BENCHMARKS DE LATENCIA

Al correr 100% en la máquina local, el plugin no envía telemetría ni texto a servidores externos. A continuación se presentan los benchmarks medidos en hardware de desarrollo estándar (AMD Ryzen 7 5800H / 16GB RAM):

Métrica Kokoro ONNX Local OpenAI TTS (tts-1) ElevenLabs Multilingual
TTFA (Time to First Audio) 120ms - 180ms 450ms - 850ms 650ms - 1200ms
Costo por 1M caracteres $0.00 (Cero Tokens) $15.00 USD $30.00 - $90.00 USD
Dependencia de Conexión 100% Offline Requiere Conexión Requiere Conexión
Privacidad de Código Total (Memoria Local) Sujeto a Cloud ToS Sujeto a Cloud ToS

[04.2] ADMINISTRACIÓN DEL SERVICIO LOCAL SYSTEMD

El daemon de Kokoro corre como servicio de usuario de systemd escuchando peticiones en el puerto local 8880:

systemd // Comandos de administración de Kokoro TTS
BASH 
# Consultar el estado del servidor Kokoro TTS local:
systemctl --user status kokoro-tts

# Reiniciar el servicio tras actualizar voces o modelos:
systemctl --user restart kokoro-tts

# Iniciar o detener manualmente el daemon:
systemctl --user start kokoro-tts
systemctl --user stop kokoro-tts

# Ver los registros en vivo del sintetizador:
journalctl --user -u kokoro-tts -f

[04.3] PIPELINE DE CLONACIÓN CON EMBEDDINGS .NPY

A diferencia de los modelos tradicionales que requieren horas de reentrenamiento, Kokoro soporta adaptación de estilo por embeddings de 512 dimensiones en formato NumPy (.npy):

Muestra de Voz (WAV 24kHz, 8s) | v Extractor de Estilo (WavLM / StyleEncoder) | v Vector de 512 Floats -> ~/.local/share/kokoro/voices/juan_carlos.npy | v Inferencia Condicionada en Tiempo Real (120ms) -> Audio Sintetizado
